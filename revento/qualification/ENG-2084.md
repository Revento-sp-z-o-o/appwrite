# ENG-2084 qualification

The ca171 build exceeded the synchronous publication deadline when updating 150
scheduled activities. Profiling located repeated relationship expansion in staging
and updateDocument, rather than PostgreSQL contention or final event reads.
This patch removes unused expansion without changing publication mode or SDKs.

## Red before implementation

On 2026-09-15, the hash-pinned ca171 native PostgreSQL fixture passed all semantic
checks and exited 255 only on the deterministic fanout budget: staging materialized
68,550 related rows and updates 137,100. Required limits are zero and 75,000.
The same fixture against the candidate passed: staging 0, updates 69,000.
Each run created and removed its own native PostgreSQL schema/cluster.

## Selected checks

- Native pooled PostgreSQL: full returned graphs, public default behavior,
  pending operation overlays, caller permissions, inverse membership, no-op dates,
  rollback, denied nested writes, unreadable-parent shape and retained link.
- Additional original/candidate comparison: relationship append/remove operators,
  nested maps and lists, dependent upsert, timestamp conflict, missing rows and
  write-only no-op authorization. Both preserve the same baseline behavior.
- Real local API: seven relationship/permission/transaction groups; legacy and
  TablesDB staging create/update/upsert/delete/increment/decrement, same/prior
  request dependencies, missing rows and rejected outsider/anonymous staging.
- Real local API/realtime: 106 operations, 105 exactly ordered events, payloads,
  staged invisibility, rollback and complete fixture/socket closure.
- Hash-pinned image build: all target installer positive/negative controls,
  syntax, capacity bootstrap and normalized read/dispatch/rollback boundary.
- Independent security, pattern and complexity reviews; no source blockers.
  CI repeats the mandatory native gates. PR bot acceptance is recorded on its head.

## Existing behavior and limits

The native baseline itself has three edge cases retained by this patch: committed
row staging overlays ignore a staged permission replacement; direct one-to-one
reassignment can reject with Duplicate until the old link is cleared; and a fully
populated update result passed to dependent upsert can duplicate a many-to-many
junction. [ENG-2086](https://linear.app/revento/issue/ENG-2086),
[ENG-2087](https://linear.app/revento/issue/ENG-2087), and
[ENG-2085](https://linear.app/revento/issue/ENG-2085) track these, respectively; the tests preserve baseline parity,
not an endorsement of these behaviors. The Program150 update path uses ID-based
update snapshots, not nested dependent upserts.

No new remote image was deployed for this qualification. The prior real dev2
Program150 synchronous failure remains failed. Acceptance still requires an
explicitly authorized dev2 deployment and repeated real Events-function publication
with revision/mirror/effect/lock correctness and deadline headroom. Removing the
fixed synchronous deadline entirely requires a separate durable async contract.
